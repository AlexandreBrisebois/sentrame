# Proposal

## Why

The application exposes identifiers and several views but does not consistently turn them into a completed investigation. The reported lost session search is present behind advanced correlation filtering in current source; restoring a recognizable workflow matters more than duplicating an unseen control.

## What Changes

- Make exact session/correlation and journey-ID investigation discoverable, scoped and persistent across views, with direct actions beside usable IDs and clear recovery.
- Give Timeline, Matching journeys, diagnostics and saved/reference paths explicit questions, evidence actions and completion outcomes without inventing conversion goals.
- Replace ambiguous stage-level hierarchy interpretation with a directed ordered-prefix path trie, retaining repeated occurrences, provenance, bounded expansion and an accessible list alternative.
- Preserve compact graph-first headers, native privacy/access/version constraints and the implemented Tools/Outils destinations.

## Capabilities

### New Capabilities

None; these are investigation behaviors in the existing capability.

### Modified Capabilities

- `journey-exploration`: exact-ID workflow, actionable investigation surfaces and directed occurrence hierarchy.

## Impact

Future work affects workspace query state, protected exact-ID validation, matching/example navigation, timeline/story/trace handoff, graph projection and saved/reference preferences. APIs already offer correlation filtering; history and the actual field must guide reuse. No production observation, runtime implementation, staged changes, archival or canonical spec synchronization is authorized. See research.md for evidence and the remediation matrix; design.md for the recommended model and trade-offs.
