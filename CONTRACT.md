# Local Release A implementation contract

For producer-facing `stage.name` semantics and minimal Event/Activity envelopes, see the [OTel event/activity contract](docs/integration/OTEL-CONTRACT.md). This file describes internal implementation boundaries, not a proprietary telemetry wire envelope.

One local synthetic app; generation persisted in settings. Go package `internal/app` owns the service. UTC timestamps in evidence are decimal nanosecond JSON strings (UI displays UTC milliseconds using BigInt conversion; exact strings survive copy). No raw OTLP is stored. Receiver is maintained Collector v0.164.0.

Evidence, Mapping, Definition and SavedView structs in `internal/app/types.go` are the shared contract. Only lead edits that file unless coordinated. Mapping kinds: `step`, `exit`, `stage-start`, `stage-end`, `activity`. Source is `browser`, `server` or empty (any). Key/value condition optional. Initial definition maps discovery.entered→Discovery, vote.requested→Intent, vote.committed→Vote (server only), publication.failed→Publication error, publication.recovered→Recovered, completion.entered→Completion (browser only), journey.exited→Exit; goal completion.entered. Diagnostics without mapping remain linked evidence if logical scope/tab matches, do not reset mapped inactivity. Scope/tab are safe random tokens; browser missing either stays unassigned. Server scope without tab is valid; combined server events carry browser tab for same logical scope. Each event records immutable active definition version. New definitions prospective; no silent retrospective resegmentation.

Protected JSON APIs under `/api/`: GET snapshot, definitions, views; POST definitions (body Definition), views (body SavedView), delete (body {scope: string} or {app:true,bucket?:YYYY-MM-DD}); POST preview (body Definition). Snapshot query: from/to ISO timestamps, version service.version, definition integer, scope optional, liveStart ISO timestamp, baseline=1, mode=historical|live. Snapshot response `{revision,now,evidence,definitions,activeDefinition,views,model,baselineModel,baselineBounds,summary,health,limits}`. `evidence` max2000 with explicit truncation; the model sees the selected bounded retained dataset, with all intermediates. Baseline ignores isolated scope; fixed seven days before liveStart. Model generated by `Derive([]Evidence, []Definition, nowNanos)` and serialized as returned. Exported model structs owned by modeling agent; frontend adapts to them.

GET /api/session returns {csrf}; POST /api/login {passphrase} sets HttpOnly owner cookie and returns {csrf}. Browser mutations include X-CSRF-Token and same Origin. POST /api/logout revokes. GET /api/events SSE invalidation {revision}, full reset on reconnect/restart/overflow, 5s invalidation covers silence; never stream evidence or keep DB transaction open. UI uses subscription generations, snapshot replacement, pause.

OTLP /v1/logs, /v1/traces, /v1/metrics on viewer origin proxies to internal maintained receiver after bound/auth checks. Authorization Bearer comes from separate SENTRAME_BROWSER_TOKEN/SENTRAME_SERVER_TOKEN environment values. Frontend never contains server token. SDKs use ordinary OTLP endpoint and headers. Producer namespace from authenticated bearer independently of self-asserted fields. Loopback internal receiver also validates bearer in consumers. HTTP binary/JSON and gzip qualification independent; gRPC not exposed initially.

Safe string projection: service.name, service.version, telemetry.sdk.language, process.runtime.name, deployment.environment.name; event.name, session.id (scope), tab.id, event.id, action.id, stage.occurrence.id, source.sequence, stage.name, stage.state, activity.state, reason, exception.type, exception.occurrence.id. Tokens constrained and bounded. Ordinary informational bodies remain omitted. Owner-approved scrubbed-v1 retains bounded standard exception messages/stacks and error-log string bodies; see the current diagnostic policy below. Unknown attributes remain omitted. Metrics inspect receipt only.

REST fixtures under rest/fixtures readable JSON describe standard OTLP JSON export requests with template NOW offset nanoseconds, scope/tab/action/record tokens. A fixture generator builds real protobuf using official protojson/proto, stores generated bodies and scenario manifest in ignored rest/generated; replay reuses exact generated file; follow-up references retained manifest scope/action. No direct SQL demo writes.

Task ownership after tracer: lead store.go/http.go/intake.go/main + auth/lifecycle/aggregation integration; model agent journey.go and journey_test.go only; UI agent web/** only; fixtures agent cmd/fixtures/**, rest/**, docs/integration/synthetic-demo.md only. The owner subsequently authorized committing and pushing this implementation; release tagging/publication waits for registry-secret setup.

SavedView also persists startOccurrence/endOccurrence (first/last); snapshot reference ID and optional endpoint overrides project maps/sequences within recorded boundaries. App-wide bounded discovered/appVersions/appScopes remain independent of view filters.

Opening by `reference=ID` restores omitted saved filters; explicit empty keys clear those defaults. Unsaved exploration uses `referenceMode`, `referenceStart`, `referenceEnd` plus first/last occurrence choices on GET snapshot; it cannot coexist with reference ID and creates no saved row. The canvas shares selection across hierarchy/force/Sankey; stage timing is in inspector/table, not node area. A visible X clears selected scope without deleting evidence.

GET /api/timeline is protected by the same owner session. It returns60 UTC half-open bins over a context selected by window=1h|24h|7d|30d, optional scope/version/record-definition filters, total, unit and truncated. It ignores graph from/to and counts retained sanitized records by occurrence time, never metric values, journeys or people. Scan limit10,000; immediate30-day expiry. The brush applies from/to to the normal snapshot query and never resegments captured journeys.


GET /api/errors: owner-protected app-wide30-day diagnostic records, optional from/to/scope/version/record-definition and q<=160 characters. Response {records,total,truncated,unit,policy}; newest10,000scan/max100returned. Standard exception.message/stacktrace and error/exception string bodies (internal log.message) are scrubbed before storage, with diagnostic.policy and optional diagnostic.truncated. Message2048 UTF-8 bytes, stack8192 bytes/40lines, input64KiB/field. Unknown attrs and INFO bodies omitted; metric labels do not create diagnostic events. Failed spans expose Error severity and permitted status text. Copy displays the same stored projection; no new identity or causality joins. Same-model replay compares all retained fields without backfill; diagnostic text never enters summaries.


App-wide temporary viewer extension (2026-10-28): owner POST/GET /api/invitations creates/lists grants; POST /api/invitations/revoke revokes. Public same-origin POST /api/invitations/redeem exchanges a one-use fragment bearer for a separate HttpOnly viewer cookie. Session/login responses include csrf, role and expires. The strict viewer read allowlist includes snapshot, definitions, views, timeline, errors and events; only logout is an allowed viewer POST. Shared mapping/reference/deletion/invitation mutations remain owner-only. Grants bind to app/generation with absolute1h/24h(default)/7d expiry; request/SSE checks enforce revocation and sessions end on restart. Stored invitation digests, capacity limits, no reused IDs and immediate revoked-session reclamation preserve the boundary.

Delivery extension: /health is liveness and /ready verifies receiver initialization plus usable SQLite. A non-root single-container image includes service, static frontend and health probe; Compose binds the existing SENTRAME_DATA_DIR into /data. GitHub publication targets brisebois/sentrame for Linux amd64 and arm64 only after checks and per-platform smoke tests. Deployment uses fresh credentials and an exact configured Origin. No actual WFS integration or shared Tunnel qualification is implied.


Standard OTel projection cutover (2026-10-29): greenfield, no legacy schema/API adapters. SQLite `user_version=3` is required; a nonempty unversioned or unsupported database fails before schema initialization with fresh-directory guidance, without automatic reset. New evidence identifies `projection=structural-v2`. Native spans retain exact decimal-string `end`, parent span ID, numeric kind/status/flags, exported event count, SDK dropped attribute/event/link counts and at most32 link target trace/span IDs with `omittedLinks`. Link attributes and trace state are omitted. Span events retain zero-based exported `eventIndex`; log flags/context remain distinct from a parent edge. Spans are immutable exports: exact app/producer/signal/span replay is idempotent; changed end/parent/event count/content/link/status conflicts atomically. Anonymous logs remain distinct. Numeric pre-cutover timestamp JSON is unsupported.

Supported HTTP selectors: `http.request.method` is one of GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS/CONNECT/TRACE; `http.response.status_code` must be an integer100–599; `http.route` is at most160 bytes, begins with `/`, and contains lowercase alphabetic/hyphen literal segments or named `{parameter}`, `:parameter`, `[parameter]` segments. Root `/` is valid. URLs, query strings, numeric segments, percent encoding, uppercase literal segments and arbitrary punctuation are omitted. Producers must supply minimized route templates; syntactic validation cannot establish that a static-looking word contains no personal content. No URL/header/database/body recovery is performed. Native timing and contextual selectors are available at the qualified local seams below; deployment and producer support remain bounded by their individual evidence cells. See [the implementation ledger](docs/verification/standard-otel.md).


Protected trace reads: GET `/api/traces` lists at most200 observed trace contexts from a10,000-record scan; GET `/api/traces/{32hexTraceId}` returns at most2,000 trace records as operations, ordered span events, logs and typed parent/span-event/log-context/link relationships. `mode=trace`, `unit=observed spans`, `computation=native-inclusive-v1`, revision, truncation and unknown completeness accompany detail. Resolved relationships never change producer authority. Missing/ambiguous parents and trace-only logs are explicit. Duration is an exact decimal nanosecond string or null with complete/right-censored/unavailable timing status. End-before-start, fallback start and absent end never become completed duration samples. Temporary viewers have these GETs on the read allowlist; mutations remain owner-only with Origin/CSRF. Trace mode has no chronological sibling edges or journey denominator. UI refresh replaces the full bounded snapshot on SSE invalidation; its automatic refresh can be paused.


Contextual mapping extension: Mapping accepts exact `service`, `signal` (traces/span-events/logs), `carrier` (span/span-event/log), `source`, event name and one allowed key/value condition. Signal/carrier must agree; metrics are not mappable. Overlap is rejected unless selectors are provably disjoint. Native-span timing is the default for a span; explicit `timing` choices are native-span/paired/estimated/none with prerequisite validation. Definition may pin `goalSelector` to one exact mapping when the goal name appears in several disjoint rules; otherwise exactly one goal-name rule is required. A goal selection never changes source authority.

Snapshot `contextualDiscovery` groups service/signal/carrier/source/name/projection and retained-field availability. Preview reports carrier-aware matches and unavailable-field/missing-journey context; absent journey scope does not disable traces. Trace detail includes `business` occurrences with stage, Kind, native identity, definition, basis, exact duration, goal and event-time/span-end boundary. Default interpretation is capture-time (receipt definition unless retained capture metadata applies); explicit GET `previewDefinition=N` is non-persisting. Failed/missing-end native spans do not satisfy completion goals. No synthetic evidence rows or new source IDs are inserted by derivation.


Native scoped integration: Model identifies `journey-native-v3`; native occurrence identity is source/trace/span and basis `native-inclusive` with `native-inclusive-v1`. Timing and journey/step boundaries serialize exact nanoseconds as decimal strings; numeric milliseconds are display/statistics units. Native goals schedule closure at valid end while preserving overlapping starts; known native interval end participates in inactivity evidence. Missing/invalid/error completion does not satisfy a native goal. Native spans are excluded from next-event estimation. Pair/presence policies remain separate; competing elapsed bases for the same stage/source/service/occurrence are excluded with an explicit conflict quality. Summaries partition computation, definition, version and timing basis without long-lived identity membership.

Schema3 includes detail-only `captureDefinition` for a late earlier prefix within the30-minute inactivity gap of a known retained scope/tab capture. Receipt `definition` remains immutable; new captures use their receipt definition. Exact replay compares the stored receipt/capture metadata without source-controlled reassignment. Unsupported schema0/1/2 or other versions fail before initialization; no automatic reset/migration exists.

SavedView mode `trace` requires a valid native trace ID, optional from/to/version filters, definition0 for capture context or a pinned explicit preview, and tree/timeline/table layout. Trace GET `reference=ID` restores those safe filters and interpretation; contradictory trace IDs/preview requests reject. Snapshot mode identifies `journey` and refuses trace-mode references. Temporary viewers can read existing references but cannot save/delete them. Detail/relationship navigation remains subject to immediate expiry/deletion.

Native browser intervals contained within a capture may additionally derive `observed-active` using `presence-cap60-browser-v2`. Presence remains browser-only, capped and explicitly observed; unobserved gaps remain unknown and server operations cannot borrow it. Exact `durationNs` for this basis measures accumulated positive intervals, not elapsed start-to-end. Projection `structural-v2` discloses `nameState`, `omittedAttributes`, SDK resource/scope dropped counts separately from span drops, and omits resource/scope custom attributes.
